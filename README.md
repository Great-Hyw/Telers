# 🏫 教育/企业管理后台系统 API

这是一个基于 **Spring Boot** 构建的后台管理系统，涵盖了员工、部门、班级、学生的核心 CRUD（增删改查）操作，以及基于 JWT 的登录认证功能。代码结构清晰，采用了经典的三层架构（Controller-Service-Mapper）。

> **注意**：根据代码审查，部分接口定义与实现可能存在不一致（如 `DeptService` 中的 `deleteEmp` 方法名），建议在使用前进行核对。

## 💻 技术栈

- **核心框架**：Spring Boot
- **ORM 框架**：MyBatis / Mapper
- **分页插件**：PageHelper
- **权限认证**：JWT (Json Web Token)
- **日志处理**：SLF4J (Lombok `@Slf4j`)
- **依赖注入**：Spring Context

## 🧩 核心功能模块

### 1. Login (登录)
处理用户的身份验证与 Token 生成。

| 方法 | 路径 | 功能描述 |
| :--- | :--- | :--- |
| `POST` | `/login` | **登录验证**：校验用户名密码，成功则生成 JWT Token 并返回给前端。 |

**逻辑细节：**
- 调用 `LoginMapper` 查询数据库。
- 使用 `JwtUtil` 生成 Token，并将其设置回 `Emp` 对象中返回。

---

### Shift+2. Employee (员工)
处理员工信息的维护，支持分页、批量删除及工作经历关联操作。

| 方法 | 路径 | 功能描述 |
| :--- | :--- | :--- |
| `GET` | `/emp/page` | **分页查询**：支持多条件分页查询员工列表。 |
| `POST` | `/emp` | **新增员工**：插入员工基础信息，并级联插入其工作经历 (`EmpExpr`)。 |
| `DELETE` | `/emp/{ids}` | **批量删除**：根据 ID 列表删除员工及其关联的工作经历记录。 |
| `PUT` | `/emp` | **修改员工**：更新员工信息，同时更新其关联的工作经历。 |
| `GET` | `/emp/{id}` | **详情查询**：根据 ID 获取单个员工的详细信息。 |

**事务管理：**
- 新增、修改、删除操作均添加了 `@Transactional` 注解，确保数据一致性。

### 3. Department (部门)
处理部门信息的维护，提供基础的增删改查功能。

| 方法 | 路径 | 功能描述 |
| :--- | :--- | :--- |
| `GET` | `/dept/all` | **查询全部**：获取所有部门列表。 |
| `POST` | `/dept` | **新增部门**：添加新部门，自动填充创建/更新时间。 |
| `PUT` | `/dept` | **修改部门**：更新部门信息，自动更新时间戳。 |
| `DELETE` | `/dept/{id}` | **删除部门**：根据 ID 删除部门。 |
| `GET` | `/dept/{id}` | **部门详情**：获取部门详细信息。 |

**注意**：接口定义中删除方法名为 `deleteEmp`，实际逻辑应为 `deleteDept`，存在命名不规范风险。

### 4. Class (班级)
处理班级信息的维护，包含状态自动计算逻辑（已开课/未开课/已结课）。

| 方法 | 路径 | 功能描述 |
| :--- | :--- | :--- |
| `GET` | `/clazz/page` | **分页查询**：支持分页查询班级列表。 |
| `POST` | `/clazz` | **新增班级**：添加班级信息。 |
| `PUT` | `/clazz` | **修改班级**：更新班级信息。 |
| `DELETE` | `/clazz/{id}` | **删除班级**：根据 ID 删除班级。 |
| `GET` | `/clazz/{id}` | **班级详情**：获取班级详细信息。 |

**特色逻辑：**
- 在查询时，后端会自动比对当前日期与班级的开班/结业日期，动态设置 `status` 字段（"已开课"、"未开课" 或 "已结课"）。

## 🗃️ 数据模型说明

- **Result**：统一响应对象，包含 `code` (状态码)、`msg` (消息)、`data` (数据)。**注意**：代码中存在拼写错误 `susses`，建议修正为 `success`。
- **PageResult**：分页结果封装，包含 `total` (总记录数) 和 `rows` (数据列表)。
- **Emp & EmpExpr**：员工与其工作经历是一对多关系，新增/修改时需同步处理子表数据。
- **JwtUtil**：负责 Token 的生成 (`CreatToken`) 和解析 (`praseToken`)，密钥和过期时间由配置文件注入。
